# 안전한 Git 작업 방법

이 프로젝트에서 `main`은 언제든 설치·검사·빌드가 성공해야 하는 공식 원본이다. 커밋하는 사람이 한 명이라 합치기 전에 다른 사람이 읽는 단계가 없으므로, 작업은 `main`에서 바로 진행한다. 공개된 이름이나 동작을 바꿔 되돌리기 어려운 변경만 작업 branch와 pull request를 사용한다.

## 작업을 시작할 때

```bash
git switch main
git pull --ff-only
```

작업 branch를 따로 만들지 않는다. 개발 서버를 띄워 둔 채 branch를 오가면 방금 만든 내용이 실행 중인 화면에서 사라져 무엇을 확인하고 있는지 알기 어려워진다.

## 작업 중 확인

```bash
git status -sb
pnpm check
```

- 사용자 결정이 필요한 `Provisional` 항목을 임의로 확정하지 않는다.
- secret, 계정 정보와 기기별 절대경로를 commit하지 않는다.
- 다른 기기에서 같은 branch를 동시에 수정하지 않는다.

## 작업을 저장할 때

```bash
git add <이번 작업 파일>
git commit -m "변경 내용을 설명하는 메시지"
git push origin main
```

push하기 전에 로컬에서 `pnpm check`를 통과시킨다. `main` push에서도 자동 검사 `Quality / Lint, test, and build`가 돌며, 실패하면 즉시 되돌리고 원인을 고친 뒤 다시 push한다.

## branch와 pull request를 사용하는 경우

공개된 이름이나 API 모양을 바꿔 소비자 코드가 컴파일되지 않는 변경은 `main`에 넣기 전에 검사 결과를 확인한다. Component의 Property 이름을 바꾸거나 Property를 제거하는 작업이 여기에 해당한다.

기본값 수치를 고치는 변경은 `main`에서 바로 한다. 이름과 API 모양이 그대로여서 소비자 코드가 깨지지 않고, 검토 중에 자주 나오는 수정이라 그때마다 검사를 기다리면 흐름이 끊긴다. 대신 로컬에서 `pnpm check`를 통과시키고 화면에서 결과를 확인한다.

```bash
git switch -c fix/작업이름
```

접두어는 기능 추가에 `feature/`, 오류 수정에 `fix/`, 문서 수정에 `docs/`를 사용한다. 자동 검사가 성공한 뒤 합치고, 목적 하나가 끝나면 branch는 지운다.

**Pull request 제목은 접두어만 영문으로 두고 설명을 한글로 쓴다.** GitHub 의 Pull requests 목록은 제목 한 줄만 보여 주므로, 무엇을 한 작업인지 목록에서 바로 읽히게 하는 자리다. 영문 설명을 뒤에 병기하지 않는다. 같은 내용을 두 언어로 적으면 제목이 길어져 목록에서 잘린다.

```
feat(badge)!: 색을 프리미티브 단계 규칙으로 정리하고 크기·모양·가이드라인 정비
```

`type(scope):` 접두어와 소비자 코드가 깨지는 변경의 `!` 표시는 커밋 제목과 같은 형식을 유지한다. 커밋 메시지는 지금까지처럼 영문 제목과 영문 본문으로 쓴다. 커밋 목록은 개발자가 읽는 자리이고 Pull request 목록은 작업 단위를 훑는 자리라서 언어를 다르게 둔다.

## 다른 기기로 이동할 때

현재 기기에서 commit과 push를 끝낸다. 다음 기기에서는 `main`을 최신화한 뒤 이어서 작업한다. 대화 내용이나 로컬 미커밋 파일은 다른 기기에 자동으로 전달되지 않는다.

## 긴급한 경우에도 지킬 원칙

급하더라도 `pnpm check`와 자동 검사를 건너뛰지 않는다. 검사가 실패한 상태로 `main`을 두지 않으며, 고치는 것보다 되돌리는 것이 빠르면 먼저 되돌린다. GitHub 장애나 인증 문제로 push하지 못했다면 해당 변경은 다른 기기에 저장된 것으로 간주하지 않는다.
